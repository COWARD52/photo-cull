# 拾片项目交接指南

> 创建时间: 2026-10-30
> 分类: 开发指南

## 适用范围

给接手 `photo-cull` 仓库的开发者或 AI 使用。**下一阶段优先优化 macOS 本地工具**；iOS 和仓库根目录的网页端先保持现状，除非用户另有要求。

仓库：<https://github.com/COWARD52/photo-cull>

## 当前代码与运行方式

- Mac 主代码在 `tools/photo_cull.py`（本地分析、评分、分组、生成报告页）、`tools/photo_cull_server.py`（仅监听 `127.0.0.1` 的本地服务及筛选操作 API）。`tools/photo_cull_vision.swift` 是可选的 macOS Vision 辅助分析。
- Mac 日常入口是 `tools/照片初筛工具.command`。它让用户选照片目录；目录已有 `_初筛结果/初筛数据.json` 时，可直接恢复报告或重新分析；再启动本地服务、打开浏览器。终端窗口关闭后服务会停止，但报告和筛选记录不会因此删除。
- Mac 首次运行使用 `tools/首次安装依赖.command`。仓库代码更新并验证后，用 `tools/同步到桌面工具.command` 更新桌面的运行副本；桌面副本不是代码主仓库。详细操作见 `tools/使用说明.txt`。
- iOS 代码在 `iOS/拣片/`；根目录 `index.html`、`app.js`、`styles.css` 属于另一个网页版本。不要把三个版本或照片目录中的 `_初筛结果/` 当作同一份源码。

## 已实现的 Mac 功能

- JPEG 等预览照片与同名 RAW 联动；清晰度、曝光、对比度、构图的启发式评分；连拍/内容相似的“对比组”；人工调整、暂存恢复、导出清单、确认后按三类整理和撤销整理。自动“淘汰”保持保守，最终决定由用户作出。
- 报告页顶部有统一“配置 AI”入口，单张“AI 帮我看看”和对比组“AI 帮我选”共用配置。AI 请求必须由用户手动发送；对比组每次最多 6 张，仅发送报告预览图，不发送 RAW 或整个相册；AI 回答不会自动改变决定。
- AI 支持 OpenAI API Key、已通过官方 `codex login` 登录的 Codex CLI，以及提供图片输入的 OpenAI Chat Completions 兼容服务。非密钥配置保存在浏览器本地存储；页面里的 API Key 只留在当前页面会话，也可由本地服务读取 `OPENAI_API_KEY` 环境变量。调用可能产生费用，测试连接也可能访问供应商；兼容服务未必支持 `/models`。
- iOS 也有手动 AI 建议代码，但本次交接不以扩展 iOS 为优先目标。不要把 Mac 的多供应商配置误写成 iOS 已支持。

## 尚未实现：跨批次“筛选偏好 Memory”

用户提出的下一阶段方向是：在**确认筛选**后，用最终人工决定生成可复用的选片偏好；后续手动 AI 选片时，把经用户确认的偏好连同所选预览图传给模型；本地初筛也可谨慎参考偏好。**这只是讨论方向，目前没有实现，不要将现有同目录阈值学习或分组反馈称为跨批次 Memory。**

建议先设计、再征求用户确认，尤其要明确：

1. 确认整理是否自动触发付费模型调用，还是单独提供“提炼偏好”按钮；默认应避免无提示费用。
2. 仅上传什么样的样本：推荐选少量最有代表性的“保留/淘汰/组内取舍”照片、压缩预览和必要的人工决定；不上传整批原片、RAW、路径或无关 EXIF。
3. Memory 应保存为本机可读、可编辑、可删除、可关闭的结构化记录，区分“用户明确偏好”和“模型推测”，附样本数、来源、生成时间与适用场景；避免把一次旅行或单个相册的偏好泛化到所有题材。
4. 后续 AI 请求可把已启用的偏好作为参考，但应标明不确定性；初筛侧先只影响提示或排序，不能仅因偏好自动淘汰。提供反馈与回退，并比较启用前后的误淘汰率、人工修改率。
5. 关注隐私、费用上限和失败恢复：模型不可用时仍可正常本地筛选；绝不因 Memory 生成失败阻断“确认筛选”。

## 接手步骤与验证

1. 克隆仓库，先读根目录 `README.md`、`tools/README.md`、`tools/使用说明.txt`，再读上述两个 Python 入口。确认 `git status` 和当前分支，勿覆盖用户的本地报告或筛选记录。
2. 在 Mac 上运行 `tools/首次安装依赖.command`；用测试照片目录验证首次分析、恢复已有报告、人工修改、对比组、暂存和整理/撤销。不要对用户的真实照片目录做破坏性测试。
3. 静态检查可运行：`python3 -m py_compile tools/photo_cull.py tools/photo_cull_server.py`、`zsh -n tools/照片初筛工具.command tools/同步到桌面工具.command`、`git diff --check`。生成报告里的 JavaScript 可另用 `node --check` 验证。
4. AI 连接测试需用户自行配置可用账号或密钥；不要将密钥、照片、`_初筛结果/`、桌面副本、Xcode 构建/签名材料提交到 Git。AI 建议的准确度尚未系统评测。
5. 完成改动后先验证，再同步桌面运行副本；仓库是唯一源代码主目录。若修改用户可见行为，同步更新相应说明。
